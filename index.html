BÁO CÁO KIẾN TRÚC & ĐẶC TẢ CHI TIẾT CÁC TÍNH NĂNG HỆ THỐNG TECHSHARE

Tài liệu này thống kê chi tiết kiến trúc, danh sách file (Frontend & Backend), danh sách hàm/phương thức, luồng dữ liệu (Data Flow) và cách các file liên kết, tương tác với nhau cho 8 tính năng cốt lõi của nền tảng TechShare.

1. TÍNH NĂNG 1: ĐĂNG NHẬP NGƯỜI DÙNG (LOGIN)

Core Auth

A. Danh sách các file tham gia

Frontend:
  • client/src/pages/LoginPage.jsx: Giao diện form đăng nhập và xử lý sự kiện submit.
  • client/src/context/AuthContext.jsx: Quản lý trạng thái xác thực toàn cục, lưu token, thông tin user và account.
  • client/src/services/api.js: Cấu hình HTTP client (Axios), tự động đính kèm JWT Bearer token và bắt lỗi 403 (khóa tài khoản).
  • client/src/routes/routes.js: Định tuyến ứng dụng, bảo vệ các trang yêu cầu đăng nhập (PrivateRoute).
Backend:
  • server/src/routes/authRoutes.js: Định tuyến endpoint API đăng nhập (POST /api/auth/login).
  • server/src/controllers/authController.js: Chứa hàm controller xử lý logic đăng nhập (login).
  • server/src/models/Account.js: Mongoose Model cho collection accounts (xác thực và bảo mật).
  • server/src/models/User.js: Mongoose Model cho collection users (thông tin hồ sơ).
  • server/src/models/Role.js: Mongoose Model cho collection roles (phân quyền).
  • server/src/config/env.js: Cấu hình Secret Key và thời hạn hết hạn của JWT (getJwtConfig).

B. Danh sách hàm/phương thức sử dụng

1. Frontend:
  • LoginPage.jsx: handleSubmit(e) - Thu thập dữ liệu form (identifier, password), kiểm tra validation, gọi API đăng nhập.
  • AuthContext.jsx:
    • login(authData): Lưu token, user, account vào React State và localStorage (techshare_token, techshare_user, techshare_account).
    • logout(): Xóa sạch dữ liệu đăng nhập khỏi State và localStorage.
  • api.js:
    • api.interceptors.request.use(): Tự động chèn header Authorization: Bearer <token>.
    • api.interceptors.response.use(): Bắt mã lỗi 401 (hết hạn phiên) và 403 (isbanned).
2. Backend:
  • authController.js:
    • login(req, res): Tiếp nhận request, xác minh thông tin tài khoản, kiểm tra khóa tài khoản, so khớp mật khẩu và ký JWT.
    • resolveRoleCode(account, user): Tra cứu mã quyền (renter, owner, admin) từ roleId trong collection roles.
    • generateToken(payload): Sử dụng thư viện jsonwebtoken để tạo chuỗi JWT.

C. Luồng hoạt động & Cách các file liên kết với nhau

Vuốt ngang để xem sơ đồ 
sequenceDiagram
    autonumber
    actor User as Người dùng
    participant LP as LoginPage.jsx
    participant AC as AuthContext.jsx
    participant AR as authRoutes.js
    participant ACtrl as authController.js
    participant DB as MongoDB (accounts, users, roles)

    User->>LP: Nhập username/email và mật khẩu, bấm Đăng nhập
    LP->>LP: handleSubmit() kiểm tra hợp lệ
    LP->>AR: POST /api/auth/login { identifier, password, portal: 'client' }
    AR->>ACtrl: Chuyển tiếp tới hàm login()
    ACtrl->>DB: Account.findOne({ username hoặc email })
    DB-->>ACtrl: Trả về tài khoản kèm passwordHash & roleId
    alt Tài khoản bị khóa (isbanned = true hoặc isActive = false)
        ACtrl-->>LP: 403 Forbidden { isbanned: true, banReason, message }
        LP-->>User: Hiển thị thông báo tài khoản bị khóa kèm lý do
    else Tài khoản hợp lệ
        ACtrl->>ACtrl: bcrypt.compare(password, account.passwordHash)
        ACtrl->>DB: User.findById(account.userId) hoặc User.findOne({ accountId })
        DB-->>ACtrl: Trả về hồ sơ User
        ACtrl->>ACtrl: resolveRoleCode() lấy mã quyền
        ACtrl->>ACtrl: generateToken({ accountId, userId, username, email, role })
        ACtrl-->>LP: 200 OK { token, account, user }
        LP->>AC: login({ token, user, account })
        AC->>AC: Lưu vào localStorage & cập nhật State
        LP->>User: Điều hướng vào trang Dashboard/Home
    end

2. TÍNH NĂNG 2: ĐĂNG NHẬP QUẢN TRỊ VIÊN (ADMIN LOGIN)

Admin Auth

A. Danh sách các file tham gia

Admin Frontend (EJS / SSR):
  • server/src/views/admin/login.ejs: Giao diện HTML/EJS trang đăng nhập dành riêng cho Admin.
  • server/src/public/js/admin/login.js: Script client-side lắng nghe submit, gọi API và lưu trữ cookie/token.
  • server/src/views/admin/layouts/main.ejs: Layout khung sườn chung của Admin Portal.
Backend:
  • server/src/routes/adminPageRoutes.js: Định tuyến render trang Admin Login (GET /admin/login).
  • server/src/controllers/admin/adminPageController.js: Controller điều hướng render giao diện EJS (renderAdminLoginPage).
  • server/src/routes/authRoutes.js: Tiếp nhận request API đăng nhập (POST /api/auth/login).
  • server/src/controllers/authController.js: Xử lý phân quyền Admin (login với portal: 'admin').
  • server/src/middlewares/adminPageAuthMiddleware.js: Middleware bảo vệ tất cả trang admin (requireAdminPageAuth).

B. Danh sách hàm/phương thức sử dụng

1. Frontend / Script:
  • public/js/admin/login.js: Lắng nghe event submit trên #adminLoginForm, kiểm tra dữ liệu đầu vào #adminIdentifier, #adminPassword, gọi fetch('/api/auth/login', { body: { identifier, password, portal: 'admin' } }).
2. Backend:
  • adminPageController.js: renderAdminLoginPage(req, res) - Kiểm tra token hợp lệ trong cookie thì chuyển hướng ngay tới /admin/dashboard, ngược lại render file admin/login.ejs.
  • authController.js: login(req, res) - Khi portal === 'admin', kiểm tra nghiêm ngặt roleCode === 'admin'. Nếu là user thường cố tình đăng nhập admin, từ chối với lỗi 401. Đồng thời thiết lập cookie bảo mật techshare_admin_token với httpOnly: true.
  • adminPageAuthMiddleware.js: requireAdminPageAuth(req, res, next) - Đọc token từ cookie techshare_admin_token, xác thực giải mã JWT, kiểm tra isbanned và quyền admin trước khi cho phép vào các trang quản trị.

C. Luồng hoạt động & Cách các file liên kết với nhau

  1. Quản trị viên truy cập /admin/login, adminPageRoutes.js gọi adminPageController.renderAdminLoginPage().
  2. Trình duyệt hiển thị login.ejs, file script public/js/admin/login.js được kích hoạt.
  3. Khi submit, script gửi POST /api/auth/login kèm cờ { portal: 'admin' }.
  4. authController.login() xác thực mật khẩu qua bcrypt, kiểm tra resolveRoleCode() có quyền admin hay không.
  5. Nếu hợp lệ, server thiết lập cookie techshare_admin_token, trả về JSON thành công.
  6. login.js nhận phản hồi và điều hướng sang /admin/dashboard.
  7. Các trang admin tiếp theo đều được kiểm soát bởi adminPageAuthMiddleware.requireAdminPageAuth().

3. TÍNH NĂNG 3: QUÊN MẬT KHẨU & KHÔI PHỤC QUA OTP (FORGOT PASSWORD)

Recovery

A. Danh sách các file tham gia

Frontend:
  • client/src/pages/ForgotPasswordPage.jsx: Giao diện 2 bước (Bước 1: Nhập email nhận OTP; Bước 2: Nhập mã 6 chữ số và mật khẩu mới).
  • client/src/services/api.js: Thực thi request API Axios.
Backend:
  • server/src/routes/authRoutes.js: Định tuyến API (/forgot-password, /reset-password, /resend-reset-otp).
  • server/src/controllers/authController.js: Xử lý sinh OTP, kiểm tra OTP và cập nhật mật khẩu.
  • server/src/services/emailService.js: Dịch vụ gửi email thông qua Nodemailer & Gmail App Password.
  • server/src/models/Otp.js: Collection otps lưu trữ mã xác minh với thời hạn 5 phút.
  • server/src/models/Account.js: Cập nhật mật khẩu mã hóa mới.

B. Danh sách hàm/phương thức sử dụng

1. Frontend (ForgotPasswordPage.jsx):
  • handleSendOtp(e): Gửi email lên backend để yêu cầu cấp mã xác thực OTP.
  • handleResetPassword(e): Gửi OTP cùng mật khẩu mới lên server để đổi mật khẩu.
  • handleResendOtp(): Kích hoạt đếm ngược 60 giây và gửi lại mã OTP mới.
2. Backend:
  • authController.js:
    • forgotPassword(req, res): Kiểm tra email có trong Account hay không, sinh mã ngẫu nhiên 6 số, lưu vào Otp với type: 'reset_password', gọi sendResetPasswordOtpEmail().
    • resetPassword(req, res): Xác thực mã OTP trong Otp, kiểm tra hạn 5 phút, mã hóa mật khẩu mới bằng bcrypt.hash() và cập nhật vào Account.
    • resendResetOtp(req, res): Làm mới mã OTP và gửi lại email.
  • emailService.js:
    • sendResetPasswordOtpEmail(toEmail, otpCode, username): Tạo transporter và gửi email HTML chứa mã OTP đặt lại mật khẩu.

C. Luồng hoạt động & Cách các file liên kết với nhau

Vuốt ngang để xem sơ đồ 
sequenceDiagram
    autonumber
    actor User as Người dùng
    participant FP as ForgotPasswordPage.jsx
    participant AR as authRoutes.js
    participant ACtrl as authController.js
    participant ES as emailService.js
    participant DB as MongoDB (accounts, otps)

    User->>FP: Nhập email, bấm "Gửi mã xác nhận"
    FP->>AR: POST /api/auth/forgot-password { email }
    AR->>ACtrl: forgotPassword()
    ACtrl->>DB: Account.findOne({ email })
    alt Email không tồn tại
        ACtrl-->>FP: 404 Không tìm thấy tài khoản
    else Email hợp lệ
        ACtrl->>ACtrl: Sinh mã ngẫu nhiên 6 chữ số
        ACtrl->>DB: Otp.findOneAndUpdate({ email, type: 'reset_password' }, { otp, expiresAt })
        ACtrl->>ES: sendResetPasswordOtpEmail(email, otpCode)
        ES-->>User: Gửi hộp thư Gmail mã OTP 6 số
        ACtrl-->>FP: 200 OK (Chuyển sang Bước 2)
    end

    User->>FP: Nhập mã OTP 6 số và Mật khẩu mới
    FP->>AR: POST /api/auth/reset-password { email, otp, newPassword }
    AR->>ACtrl: resetPassword()
    ACtrl->>DB: Otp.findOne({ email, type: 'reset_password' })
    ACtrl->>ACtrl: So khớp OTP & hạn 5 phút
    ACtrl->>ACtrl: bcrypt.hash(newPassword, salt)
    ACtrl->>DB: Account.updateOne({ email }, { passwordHash })
    ACtrl->>DB: Otp.deleteOne({ _id })
    ACtrl-->>FP: 200 OK Thành công
    FP-->>User: Thông báo thành công và chuyển hướng sang /login

4. TÍNH NĂNG 4: XÁC THỰC DANH TÍNH NGƯỜI THUÊ (eKYC RENTER)

Verification

A. Danh sách các file tham gia

Client Frontend:
  • client/src/pages/ProfilePage.jsx: Hiển thị huy hiệu trạng thái eKYC (eKYC Verified, eKYC Under Review, Not Verified) và nút mở modal.
  • client/src/components/ekyc/EkycSubmitModal.jsx: Modal form tải ảnh 2 mặt CCCD và thông tin cá nhân.
  • client/src/services/uploadService.js: Upload ảnh trực tiếp lên Cloudinary.
  • client/src/services/api.js: Gọi các API /api/ekyc/status và /api/ekyc/submit.
Admin Moderation & Backend:
  • server/src/views/admin/ekyc-verification.ejs: Giao diện duyệt đơn eKYC người thuê (chỉ 2 ảnh: Mặt trước, Mặt sau).
  • server/src/public/js/admin/ekyc-verification.js: Xử lý xem chi tiết ảnh, kiểm tra validation lý do từ chối (bắt buộc nhập nếu từ chối, có viền đỏ cảnh báo thay thế alert native).
  • server/src/routes/ekycRoutes.js: Endpoint nộp và tra cứu đơn (/api/ekyc/status, /api/ekyc/submit).
  • server/src/controllers/ekycController.js: Controller tiếp nhận hồ sơ người thuê.
  • server/src/routes/adminPageRoutes.js: Route render trang duyệt eKYC người thuê (/admin/ekyc-verification).
  • server/src/routes/adminEkycRoutes.js: Endpoint duyệt/từ chối của Admin (PATCH /api/admin/ekyc/:id/status).
  • server/src/controllers/adminEkycController.js: Xử lý phê duyệt, cập nhật trạng thái isVerified = true cho User & Account.
  • server/src/models/EkycRequest.js: Bắt buộc gắn chặt với collection ekyc_requests.

B. Danh sách hàm/phương thức sử dụng

1. Frontend:
  • ProfilePage.jsx: useEffect gọi /api/ekyc/status để kiểm tra tiến độ duyệt.
  • EkycSubmitModal.jsx:
    • handleImageSelect(side, file): Đọc và preview ảnh CCCD.
    • handleSubmit(e): Upload ảnh qua uploadToCloudinaryDirect, sau đó gửi thông tin lên backend.
2. Backend:
  • ekycController.js:
    • getMyEkycStatus(req, res): Truy vấn đơn eKYC mới nhất từ collection ekyc_requests.
    • submitEkycRequest(req, res): Tạo đơn mới với status: 'pending', lưu link ảnh CCCD và thông tin định danh.
  • adminPageController.js:
    • renderEkycVerificationPage(req, res): Đọc danh sách từ collection ekyc_requests, kết hợp với users để render bảng duyệt.
  • adminEkycController.js:
    • updateEkycStatus(req, res): Nếu Approved -> Cập nhật EkycRequest.status = 'approved', đồng thời cập nhật users.trust.isVerified = true và accounts.isVerified = true. Nếu Rejected -> Cập nhật EkycRequest.status = 'rejected' và lưu rejectionReason. Gửi thông báo đẩy (Notification) tới người dùng.

C. Luồng hoạt động & Cách các file liên kết với nhau

  1. Người thuê mở ProfilePage.jsx, bấm nộp eKYC để mở EkycSubmitModal.jsx.
  2. Ảnh CCCD được đẩy lên Cloudinary qua uploadService.js, sau đó gửi POST /api/ekyc/submit.
  3. ekycController.submitEkycRequest() ghi bản ghi mới vào collection ekyc_requests.
  4. Admin truy cập /admin/ekyc-verification. adminPageController.js truy vấn độc quyền collection ekyc_requests và render file ekyc-verification.ejs.
  5. Admin xem 2 ảnh, chọn Duyệt hoặc Từ chối:
    • Nếu từ chối mà không nhập lý do, public/js/admin/ekyc-verification.js hiển thị viền đỏ và thông báo inline bắt buộc.
    • Khi bấm xác nhận, gọi PATCH /api/admin/ekyc/:id/status.
  6. adminEkycController.updateEkycStatus() cập nhật trạng thái approved/rejected, đồng bộ isVerified = true vào cả 2 bảng users và accounts.
  7. Đơn sau khi duyệt xong sẽ khóa chỉ cho xem chi tiết (Xem chi tiết), không cho phép chỉnh sửa lại.

5. TÍNH NĂNG 5: NÂNG CẤP CHỦ THIẾT BỊ (eKYC OWNER UPGRADE)

Role Upgrade

  • client/src/components/ekyc/OwnerEkycSubmitModal.jsx: Modal nộp hồ sơ nâng cấp chủ thiết bị yêu cầu đủ 3 ảnh: Mặt trước, Mặt sau và Ảnh chân dung cầm CCCD.

Admin Moderation & Backend:
  • server/src/views/admin/owner-ekyc-verification.ejs: Giao diện duyệt đơn nâng cấp chủ máy (hiển thị 3 khung ảnh).
  • server/src/public/js/admin/owner-ekyc-verification.js: Xử lý mở modal kiểm tra 3 ảnh, validate lý do từ chối inline.
  • server/src/routes/ownerEkycRoutes.js: Định tuyến API (/api/owner-ekyc/status, /api/owner-ekyc/submit).
  • server/src/controllers/ownerEkycController.js: Controller kiểm tra điều kiện và nhận đơn.
  • server/src/routes/adminPageRoutes.js: Route render trang duyệt chủ máy (/admin/owner-verification).
  • server/src/routes/adminOwnerEkycRoutes.js: API duyệt của Admin (PATCH /api/admin/owner-ekyc/:id/status).
  • server/src/controllers/adminOwnerEkycController.js: Nâng quyền tài khoản lên owner trong cả accounts (roleId) và users (role).
  • server/src/models/OwnerEkycRequest.js: Gắn chặt với collection owner_request.

B. Danh sách hàm/phương thức sử dụng

1. Frontend:
  • ownerEkycService.js:
    • getMyOwnerEkycStatus(): Tra cứu trạng thái đơn từ /api/owner-ekyc/status.
    • submitOwnerEkycRequest(data): Gửi 3 link ảnh và thông tin lên /api/owner-ekyc/submit.
  • OwnerEkycSubmitModal.jsx: Quản lý 3 trạng thái upload (idCardFront, idCardBack, selfieHoldingId).
2. Backend:
  • ownerEkycController.js:
    • submitOwnerEkycRequest(req, res): Kiểm tra user đã hoàn tất eKYC người thuê chưa, kiểm tra đủ 3 ảnh, lưu vào collection owner_request.
    • getMyOwnerEkycStatus(req, res): Lấy đơn từ OwnerEkycRequest.
  • adminPageController.js:
    • renderOwnerEkycVerificationPage(req, res): Truy vấn độc quyền từ collection owner_request và render owner-ekyc-verification.ejs.
  • adminOwnerEkycController.js:
    • updateOwnerEkycStatus(req, res): Nếu Approved -> Cập nhật OwnerEkycRequest.status = 'approved', đổi roleId trong accounts sang mã owner, cập nhật role: 'owner' trong users. Nếu Rejected -> Cập nhật status = 'rejected', ghi nhận lý do từ chối.

C. Luồng hoạt động & Cách các file liên kết với nhau

  1. Người thuê đủ điều kiện bấm "Upgrade to Owner" trên ProfilePage.jsx.
  2. Modal OwnerEkycSubmitModal.jsx yêu cầu chọn và tải 3 ảnh lên Cloudinary, sau đó gọi ownerEkycService.submitOwnerEkycRequest().
  3. Backend ownerEkycController.js lưu đơn vào collection owner_request.
  4. Admin truy cập /admin/owner-verification, adminPageController.js render owner-ekyc-verification.ejs với danh sách đơn nâng cấp.
  5. Admin mở modal xem đủ 3 ảnh (đặc biệt là ảnh chân dung cầm CCCD).
  6. Khi duyệt: adminOwnerEkycController.js tự động tra cứu quyền owner từ collection roles và gán lại roleId trong accounts, đổi role trong users thành 'owner'.
  7. Người dùng lập tức có quyền truy cập Owner Dashboard và đăng thiết bị cho thuê.

6. TÍNH NĂNG 6: ĐĂNG KÝ TÀI KHOẢN & KÍCH HOẠT OTP (REGISTER)

Onboarding

A. Danh sách các file tham gia

Frontend:
  • client/src/pages/RegisterPage.jsx: Giao diện 2 bước (Bước 1: Điền thông tin cá nhân; Bước 2: Nhập mã xác minh OTP 6 số).
  • client/src/context/AuthContext.jsx: Nhận token và tài khoản sau khi kích hoạt để đăng nhập tự động.
  • client/src/services/api.js: Gọi API /api/auth/register-init và /api/auth/register-verify-otp.
Backend:
  • server/src/routes/authRoutes.js: Định tuyến API đăng ký (/register-init, /register-verify-otp, /resend-otp).
  • server/src/controllers/authController.js: Xử lý kiểm tra trùng lặp, gửi OTP, tạo tài khoản nguyên tử kèm cơ chế Rollback.
  • server/src/services/emailService.js: Gửi mã OTP xác thực đăng ký qua email.

  • handleInitSubmit(e): Kiểm tra độ mạnh mật khẩu, trùng khớp mật khẩu, gọi /api/auth/register-init.
  • handleVerifyOtp(e): Thu thập 6 số OTP và gửi lên /api/auth/register-verify-otp.
  • handleResendOtp(): Yêu cầu cấp lại mã OTP mới.
2. Backend (authController.js):
  • registerInit(req, res): Kiểm tra dữ liệu bắt buộc (username >= 3 ký tự, email hợp lệ, password >= 6 ký tự). Kiểm tra trùng lặp: Nếu phát hiện tài khoản mồ côi (có trong accounts nhưng không có trong users), tự động dọn dẹp để người dùng đăng ký lại bình thường. Sinh mã OTP 6 số, mã hóa mật khẩu qua bcrypt.hash(). Lưu vào collection otps (hạn 5 phút) và gọi sendOtpEmail().
  • registerVerifyOtp(req, res): So khớp mã OTP. Khởi tạo đồng bộ ObjectId cho cả 2 collection (accountId, userId). Lưu newAccount vào accounts. Sinh mã giới thiệu duy nhất referralCode (ví dụ TS...) và lưu newUser vào users.
    ⚡ Cơ chế Rollback: Bọc newUser.save() trong try/catch. Nếu lưu User thất bại, lập tức xóa newAccount để không bao giờ phát sinh tài khoản rác/mồ côi.

B. Danh sách hàm/phương thức sử dụng

  • fetchUserProfile(): Gọi api.get('/auth/profile') mỗi khi tải hoặc reload trang.
  • handleAvatarUpload(e): Nén ảnh và upload lên Cloudinary, gọi api.post('/users/avatar').
  • handleSaveProfile(e): Cập nhật họ tên, số điện thoại, địa chỉ qua api.patch('/users/profile').
2. Backend & Formula Engine:

reviewService.js: syncUserRatingAndTrustScore(userId)

  • Quét tất cả review hợp lệ trong collection reviews (và rating/ratings nếu có).
  • Tính totalReviews (số lượng review) và avgRating = sum / count (làm tròn 1 số thập phân).
  • Tính toán trustScore theo công thức bên dưới:
$$\text{trustScore} = \min(100, \max(50, \text{round}(\text{avgRating} \times 20)))$$
  • Cập nhật trực tiếp các trường rating, totalReviews, trust.score, trustScore vào collection users trong MongoDB.
  • authController.js:
    • getProfile(req, res): Tự động gọi syncUserRatingAndTrustScore() trước khi trả dữ liệu User cho Client.
    • getCurrentUser(req, res): Tương tự, đồng bộ danh tiếng người dùng khi gọi /api/auth/me.
    • updateAvatar(req, res): Lưu link ảnh mới vào DB và xóa ảnh đại diện cũ trên Cloudinary.
    • updateProfile(req, res): Cập nhật thông tin định danh và địa chỉ.

C. Luồng hoạt động & Cách các file liên kết với nhau

  1. Người dùng mở hoặc F5 lại trang Profile, ProfilePage.jsx kích hoạt fetchUserProfile().
  2. Client gửi GET /api/auth/profile.
  3. authController.getProfile() tiếp nhận request và gọi reviewService.syncUserRatingAndTrustScore(userId).
  4. syncUserRatingAndTrustScore():
    • Truy vấn collection reviews để tìm tất cả các review mà user là bên nhận (chủ máy hoặc người thuê).
    • Tính toán lại trung bình cộng số sao và quy đổi sang điểm tín nhiệm Trust Score theo thang 100.
    • Ghi đè các giá trị mới (rating, totalReviews, trust.score, trustScore) vào collection users trong MongoDB.
  5. authController.getProfile() trả dữ liệu User đã được cập nhật về cho Client.
  6. ProfilePage.jsx nhận response, hiển thị:
    • Trust Score: {profile.trustScore ?? profile.trust?.score ?? 100} / 100
